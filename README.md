# AutoLoc — Vehicle Rental Management

AutoLoc is a Java and Spring Boot application for managing the core information of a vehicle-rental company. It is developed in stages as part of course workshops.

## Project overview

The project models the main concepts of a rental agency:

- **Agency and employees**: agency information and employee roles (`AGENT`, `MANAGER`).
- **Vehicles**: registration number, make, model, category, daily rate, and status.
- **Customers and reservations**: customer details, driving-licence information, reservation dates, and status.
- **Contracts and payments**: contract details and totals, payment dates, amounts, and methods.
- **Maintenance and equipment**: vehicle maintenance records and equipment labels.

The domain package contains entities for `Agence`, `Client`, `Contrat`, `Employe`, `Equipement`, `Maintenance`, `Paiement`, `Reservation`, and `Vehicule`. Enums represent vehicle categories and statuses, reservation status, employee roles, and payment methods. Employees can be assigned to an agency through a many-to-one relationship. Other entity relationships are planned for a later development stage.

## Current implementation

- `AutoLocationApplication` is the Spring Boot entry point.
- Each domain entity has a Spring Data repository, a concrete service class, and a REST controller with CRUD operations.
- Controllers follow the request flow: controller → service → repository → database.
- SpringDoc generates the OpenAPI description and Swagger UI from the REST controllers. `@Tag` and `@Operation` annotations describe API groups and operations.
- The project exposes REST APIs; it does not include browser pages.

- A running MySQL or MariaDB database server

## Database and persistence

The project is configured to use a MySQL database named `autoloc_db`. Database credentials can be supplied through the `DB_USERNAME` and `DB_PASSWORD` environment variables. The JDBC configuration can create the database if it does not exist, depending on the permissions of the configured database user. An optional SQL script is available at `sql/autoloc_db.sql`.

Hibernate is configured with `spring.jpa.hibernate.ddl-auto=update`, so it creates or updates tables from the mapped entities when the application starts. This is intended for development and learning.

## Run the application

1. Start the MySQL or MariaDB database server.
2. Open the project in IntelliJ IDEA and load `pom.xml` as a Maven project.
3. Run `tn.esprit.spring.AutoLocationApplication` from IntelliJ IDEA.

Alternatively, run the Maven Wrapper from the project root:

```bash
./mvnw spring-boot:run
```

On Windows PowerShell:

```powershell
.\mvnw.cmd spring-boot:run
```

## API documentation

After starting the application, open Swagger UI at `/swagger-ui/index.html` and the generated OpenAPI document at `/v3/api-docs`. If a servlet context path is configured, prepend it to either path. Swagger UI lists the CRUD operations for the project entities and lets you send requests to them.

With the default configuration, Swagger UI is available at `http://localhost:8081/swagger-ui/index.html`.

The API resources are `/agences`, `/clients`, `/contrats`, `/employes`, `/equipements`, `/maintenances`, `/paiements`, `/reservations`, and `/vehicules`:

| Method | Path | Result |
| --- | --- | --- |
| POST | `/{resource}` | Create an entity (201) |
| GET | `/{resource}/listall` | List all entities (200) |
| GET | `/{resource}/{id}` | Read an entity (200) |
| PUT | `/{resource}/{id}` | Update an entity (200) |
| DELETE | `/{resource}/{id}` | Delete an entity (204) |

Missing entities return 404; absent or malformed JSON request bodies return 400. The existing `/`, `/employes`, and `/employes/test` GET endpoints remain available.

IDs are generated by the database and are read-only in Swagger request examples. POST always creates a new entity, even if a client sends an ID. To test in Swagger or Postman, POST first, copy the ID returned in the response, then use it for GET, PUT, and DELETE. GET `/{resource}/listall` lists the records; an empty array is a successful response when no records exist.

## Verification

Run `./mvnw verify` (or `.\mvnw.cmd verify` on Windows). Integration tests start the HTTP server on a random port and use an isolated H2 in-memory database, so MySQL is not required for tests. They check Swagger UI, OpenAPI, CRUD operations for all nine entities, the existing employee routes, missing entities, and malformed JSON. Normal application startup continues to use MySQL.

## Completion against SpringBoot-main

Springbooteasy originally provided the domain model, employee CRUD, and employee/vehicle repositories. The missing agency, customer, contract, equipment, maintenance, payment, reservation, and vehicle API layers have been added from SpringBoot-main, together with API error handling, Swagger documentation, and integration tests. The original `AutoLocationApplication` entry point, `autoloc-api` artifact name, explicit entity constructors, database settings, and home endpoint are retained.

## Current scope

The REST endpoints manage the entities and their fields. Employees reference an agency through `@ManyToOne`; multiple employees may share an agency. Other entity relationships can be added as the corresponding JPA associations are introduced in the course.

## Assign an employee to an agency

`IEmployee` is the service interface (the contract). `EmployeService implements IEmployee` provides the implementation and receives both `EmployeRepository` and `AgenceRepository` through constructor injection. `EmployeController` depends on the interface.

The method `Employe affecterAgenceEmploye(long idAgence, long idEmploye)` loads the two existing records, sets the employee's agency, saves the employee in a transaction, and returns it. Missing records return 404. Assigning again replaces the employee's previous agency. Agencies are not created or deleted by assigning or deleting an employee.

1. POST `/agences` to create an agency and copy `idAgence` from the response.
2. POST `/employes` to create an employee and copy `idEmploye`.
3. PUT `/employes/{idEmploye}/agence/{idAgence}` with no request body.
4. GET `/employes/{idEmploye}` to see the saved `agence` object.

For example, `PUT http://localhost:8081/employes/5/agence/2` assigns employee 5 to agency 2. The assignment endpoint appears in Swagger under Employés. The `agence` field is read-only in employee JSON requests; use the assignment endpoint to change it. Existing employees may remain unassigned. Delete assigned employees before deleting their agency.
